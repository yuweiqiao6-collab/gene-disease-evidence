# 使用自己的模型接口和密钥

代码下载者可以自行部署，并使用自己的API key（模型接口密钥）。GitHub（代码托管平台）保存代码，不提供模型额度，也不会自动运行应用。
如果多人访问同一个已部署网页，当前版本使用该部署端配置的模型密钥；不支持每位访客在网页上临时输入个人密钥。

0.12.0网页调用的是“疾病组相对正常对照的表达差异”任务；只发送所选材料中的有限候选及相邻上下文，不自动发送全库。
正文每组最多9000字符，另有任务说明与来源信息，默认不重试；费用由服务商计量，程序显示的词元用量不能替代账单。
新增Europe PMC（欧洲生物医学文献平台）独立检索不需要模型密钥，也不调用模型。

## 1. 配置在哪里

在自己的项目根目录，将 `.env.example`（空密钥配置模板）复制成私有的 `.env`。
**已有 `.env` 时先保留并检查，不要覆盖。** 本机可能只读引用另一个已有模型配置，不需要重新复制密钥。

按自己的服务填写：

```dotenv
RAG_ENABLE_LITERATURE=true
RAG_ENABLE_LIVE=true
RAG_ACCESS_PASSWORD=
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL=
RAG_MODEL_ENV_FILE=
```

| 配置名 | 中文含义与填写方式 |
|---|---|
| RAG_ENABLE_LITERATURE | 在线文献开关；true表示开启，false表示关闭。不调用模型 |
| RAG_ENABLE_LIVE | 真实模型抽取开关；true表示开启，false表示关闭 |
| RAG_ACCESS_PASSWORD | 自己设置至少12字符的网页访问口令，与模型密钥不同 |
| LLM_API_KEY | 自己的模型服务密钥 |
| LLM_BASE_URL | 服务商给出的接口基础地址，不含末尾的 /chat/completions 路径 |
| LLM_MODEL | 服务商要求的模型标识；必须与自己的服务和权限匹配 |
| RAG_MODEL_ENV_FILE | 可选的已有私有模型配置路径；直接填自己的配置时通常留空 |

三个模型字段必须一起核对，不能只换密钥而保留原服务地址或错误的模型名称。
本项目向基础地址后追加 `/chat/completions`，使用 `Bearer`（持有密钥的身份验证）和聊天消息格式发送请求，并要求模型返回结构化结果。
不是所有模型服务都兼容；有独有接口格式的服务需另写适配代码，推理型模型的输出格式与参数也需实际验证。
页面显示“已配置”仅表示密钥和模型名称非空，不是服务可用性认证。

## 2. 重启自己的应用进程

配置读取以进程已有环境变量优先，再读取本项目私有配置；`RAG_MODEL_ENV_FILE`只补充模型配置中未直接提供的值。
换成全新个人配置时，若不再使用原配置引用，应清空该路径，避免混用不同服务的地址、名称和密钥。
修改后需要完整重启自己的应用进程，不能只刷新浏览器。不要同时启动两个共用同一运行目录的进程。

已有环境在项目目录执行：

```bash
source .venv-release/bin/activate
bash scripts/run_local.sh
```

新下载的源码先按[中文首页](../README.zh-CN.md)建立环境，再使用相应环境启动。
如果启动命令前写了 `RAG_ENABLE_LIVE=false`，它会优先关闭真实抽取，即使文件中写的是开启。

## 3. 在页面使用

1. 顶部检查文献检索是否开启、模型是否已配置、真实抽取是否启用。
2. 在侧栏填写自己配置的“真实抽取访问口令”。不要把API key填进这个框。
3. 在“真实文献与模型抽取”第一步选择本地、混合或仅PubMed，输入基因和疾病，检索候选。
4. 第二步默认扫描当前全部候选；可展开单篇预览或单独获取开放正文。需要少量手动抽取时才切换模式并选择最多五篇。自有文献接入见[全文库指南](FULL_LIBRARY.md)。
5. 第三步核对目标、文本范围与请求预算，勾选允许外发后开始。批量暂停与继续见[扫描指南](BATCH_SCAN_GUIDE.md)。

启动应用、检索PubMed或获取正文不会自动调用模型。真实抽取可能按服务商规则收费，篇数不等于调用次数；候选片段、失败重试和缓存都会影响用量。
不要将 `.env`、密钥、恢复码或私有论文放进公开仓库。发布包只保留空密钥模板。

## 复用原项目检索流程

这一路沿用原候选筛选算法：本地BM25粗筛和PubMed摘要合并，读取或补算候选向量，再融合排名、重排序。不会先计算全库向量。
网页与终端使用同版检索核心；当前网页的LLM任务仍为疾病相对正常对照表达比较。原终端的宽泛关系任务不会被悄悄替换成新任务。

已有原项目时，在网页项目根目录执行一次，替换为自己的路径：

```bash
python scripts/configure_original.py --source /path/to/rag_gene_disease_extractor --python /path/to/existing-model-env/bin/python
```

脚本只新建私有.env.original，记录原BM25 JSON（结构化文本）索引、两个本地模型和Python（程序运行环境）位置；不覆盖双方.env、不拷贝索引、不下载或安装模型。
模型环境需要已有sentence-transformers（文本向量与排序工具）、torch（模型计算框架）和numpy（数组计算工具）。网页可继续使用原轻量环境，模型计算在独立本地进程执行，默认两个CPU（中央处理器）线程，不占用未分配GPU（显卡）。
原索引JSON可能较大，首次读取与未缓存片段编码可能耗时较长；缓存仅免去对应片段的重复编码，不保证整条查询瞬时完成。

保存研究空间恢复码，再停止自己运行的旧网页并重新启动：

```bash
bash scripts/run_local.sh
```

进入“真实文献与模型抽取”，选择“混合检索与精排”。先点“检索并精排（不调用LLM）”，这一步不调用LLM；检查来源、实际方法和最终片段数后，填写访问口令、勾选外发确认，再调用LLM。片段上限按整次查询计算，不是每篇各取5或15组。
默认粗筛和向量池上限均为500，最终12组；可选5、10或15组。每篇数量限制默认关闭，保留原设置。网上文献开关关闭时只使用本地库，也不查询自动别名。

.env.original属于私有部署配置，不上传GitHub。模型或索引不可用时明确显示错误；请求混合检索但实际退回关键词时，不能直接提交这批结果给LLM。

旧408份向量缓存没有覆盖。旧文件缺少模型版本记录，不自动认定为当前有效缓存；新缓存绑定原文、模型版本和编码规则，只计算缺失片段。同一段文字跨查询复用，新查询的名次与来源仍使用新输入记录。

没有原索引但已有逐行JSON原片段时，可自行建立兼容索引：

```bash
python scripts/build_original_index.py --chunks /path/to/chunks.jsonl --output /path/to/new-bm25-index.json
```

每行至少包含chunk_id（片段编号）、paper_id（文献编号）、context（原文），建议同时保留title（标题）、file_name（文件名）、page（页码）和source_location（来源位置）。此命令不重新分片、不生成向量，也不覆盖已有索引。配置文件可手动指向这个新索引；更换分片输入后不能把旧缓存直接当作兼容。

比较最终预算时，用模型环境运行scripts/compare_original_retrieval.py，提供固定索引、基因、疾病和新输出目录；可用--recorded-online提供已保存摘要。它只比较5／10／15组，禁止在线接口，不调用LLM，输出比较记录和空白人工相关性表。无完整人工参考时不计算召回率，正文字符数不冒充模型词元数。
