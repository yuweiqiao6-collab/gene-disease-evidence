# 本地部署与后续发布

## 集群环境约束

优先使用项目独立虚拟环境，不需要安装Docker（容器工具）或系统服务。
启动脚本只监听本机地址，并限制数值计算线程数；仍会使用运行节点的处理器、内存和磁盘。
服务应运行在集群允许交互应用的节点。启动器只核实并复用或恢复本账号、本项目的网页进程，不强制结束未知端口占用者。

## 1. 当前机器直接运行

支持本地全文库和可选在线检索。加载新版时由使用者重启自己的应用进程，再刷新浏览器。在线文献服务默认开启，模型真实抽取仍由独立开关控制。
`RAG_ENABLE_LITERATURE=false` 可关闭在线检索和全文请求；本地检索和已保存候选仍可使用。
已有私有配置没有这个变量时默认开启。详情见[文献检索指南](LITERATURE_GUIDE.md)。

在项目目录执行[英文首页](../README.md)或[中文首页](../README.zh-CN.md)中的安装命令。无需密钥即可体验人工示例。
`requirements-lock.txt` 固定完整依赖，包含测试工具；`requirements.txt` 记录直接依赖。
真实抽取需要管理员提供接口地址、模型名称和密钥，并设置至少 12 字符的共享访问口令。
下载者可以自行配置兼容的模型服务；公共页面访客临时输入个人密钥尚未实现，步骤见[模型配置说明](MODEL_SETUP.md)。

运行目录默认为项目中的 `.runtime/`，不进入源码或发布包。生产使用可将 `RAG_RUNTIME_DIR` 设置为独立绝对路径。
历史和复核结果保存在 `history.sqlite`，用私有恢复码找回，数据库只保存恢复码摘要。
文献收藏单独保存在同一运行目录的 `literature.sqlite`；备份时一并保留。
上传原文、候选快照等临时文件最长保留 24 小时，达到 200 个任务时会提前清理旧的已完成任务文件。
历史中的证据及已引用上下文持续保存，直到手动删除历史；停机后备份私有运行目录与配置。
批量扫描的候选文字、调用检查点和模型缓存保存在同目录的`scans/`，持续保存；删除对应历史任务时一起删除。
不要按临时任务的24小时规则清除`scans/`；服务重启后可用恢复码找回扫描，确认预算后继续，未知结果不自动重发。
清理由页面轮询、任务提交和服务启动触发；服务停机期间不会自动清理，启动时会清理过期任务。
恢复历史需要自己保存的恢复码；真实抽取访问验证在恢复后要重新进行。重启时未完成任务标为中断，不自动继续付费请求。
同一运行目录只允许运行一个进程；应使用支持文件锁的存储，当前没有验证集群所有存储类型。

已有环境可直接执行`bash scripts/run_local.sh`；脚本优先使用已激活的环境，再查找`.venv-release/`和`.venv/`，不重复安装。
下载者需自行配置模型和本地文献库；开发环境的文献与私有配置不随代码发布。自有PDF接入见[全文库指南](FULL_LIBRARY.md)，评测见[阶段评估报告](PORTFOLIO_REPORT.md)。
完全不联网的人工演示可在启动命令前设置 `RAG_ENABLE_LIVE=false RAG_ENABLE_LITERATURE=false`，详见[五分钟演示](SHOWCASE.md)。

## 2. 从个人电脑访问远程服务器

当前启动脚本只监听本机地址，不会自动对公网开放。
如果远程开发工具已有端口转发，可直接点击终端网址，无需另开个人电脑终端。
没有转发通道时，再在个人电脑运行SSH（加密远程连接）端口转发；把示例替换为自己的服务器信息：

```bash
ssh -L 8501:127.0.0.1:8501 USER@SERVER
```

保持连接，在个人电脑浏览器打开 `http://127.0.0.1:8501`。
这一步无需购买域名，但需要有服务器访问权限。

## 3. Docker 容器部署

Docker 是把应用与依赖打包运行的容器工具。机器需要安装 Docker 和 Compose（容器编排工具），且容器服务已启动。

```bash
docker compose up --build -d
```

然后在同机打开 `http://127.0.0.1:8501`。默认只开放本机端口，任务数据保存在独立数据卷中。
应用以普通用户运行。容器使用固定 Python 依赖，基础镜像为 Python 3.12；尚未锁定镜像摘要。
提供容器配置模板，尚未验证镜像构建或容器实际运行。

需要启用真实模型时，在项目 `.env` 中填写值，Compose 会将指定变量注入容器；该文件不复制进镜像。
需要公共语料库时，额外增加只读挂载与环境变量，例如：

```yaml
    environment:
      RAG_CORPUS_DB: /corpus/corpus.sqlite
    volumes:
      - task-data:/app/.runtime
      - /srv/gene-evidence/corpus.sqlite:/corpus/corpus.sqlite:ro
```

这是对现有配置的补充，请保留原有环境变量和数据卷。数据库由管理员在宿主机预先生成。

## 4. 后续公开上线

当前交付本地运行与源码发布包，尚未确定正式托管平台。
准备正式上线时，需要可运行 Python 的托管环境、域名或可访问地址，以及 HTTPS（加密网页连接）和 WebSocket（持续网页连接）支持。
GitHub Pages 是静态网页托管服务，不能直接运行本应用。[GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

当前实现以单进程运行，固定 2 个后台工作线程、4 个排队位置；每个会话每分钟最多 3 个任务，整个进程每小时最多 60 个任务、其中真实任务最多 20 个。
这是共享访问口令加任务隔离，不是完整的用户账号系统；口令仅用于控制真实模式的访问和费用。
已支持持久历史与复核；多副本、机构账号、中断任务自动续跑与大规模并发需要后续单独建设。

## 5. GitHub 公开仓库

目标账号：`yuweiqiao6-collab`。建议仓库名：`gene-disease-evidence-app`。
提供完整源码包与自动分成每批不超过100个文件的网页上传包，步骤见[上传指引](GITHUB_UPLOAD.md)。生成本地发布包不会自动登录或更新远端仓库。
源码中的 `.gitignore`（版本控制忽略规则）排除了密钥及备份、文献、模型、缓存、任务结果和虚拟环境。
首次推送前执行发布检查，并由项目所有者确认代码权属和 LICENSE（使用许可证）。

推荐直接下载本地发布包，在个人电脑解压后通过网页上传，见[逐步上传说明](GITHUB_UPLOAD.md)。
这样不需要在集群存放 GitHub 凭据，也不涉及运行服务。

如果以后希望使用命令行管理，请在解压后的干净发布目录中初始化 Git（版本管理工具），检查暂存文件后配置远程地址：

```bash
git init -b main
git add .
git status --short
git commit -m "Initial evidence workbench release"
git remote add origin https://github.com/yuweiqiao6-collab/gene-disease-evidence-app.git
git push -u origin main
```

用户提供了此目标仓库；本轮没有核验远端最新内容。已有仓库使用克隆后更新文件的方式，避免重复初始化或强制推送。
上述首次初始化命令仅适用于空仓库。不要在原研究目录执行整目录上传。
提交时需要在个人电脑配置 Git 的提交者姓名和邮箱；如不希望公开真实邮箱，可以使用 GitHub 提供的隐私邮箱。
本轮没有在集群初始化远程连接、设置全局 Git 配置、登录或推送。

## 原流程适配部署

原索引、两个本地模型和模型环境通过私有.env.original配置，步骤见[模型配置](MODEL_SETUP.md#复用原项目检索流程)。网页环境可保持轻量，排序计算通过本机独立工作进程调用同版原核心。默认限制两个CPU线程，不使用未分配显卡；这不等同于验证了全库冷启动的内存与延迟。
代码上传GitHub不包含原5GB索引或模型。新部署者需提供自己的资源；原文分片或评分方式改变时，先比较候选差异和缓存兼容性，不自动重建已有库。
