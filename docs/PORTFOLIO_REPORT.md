# 小型效果与失败分析

版本0.10.0，整理日期2026-10-19。这里分别记录教学流程、真实本地检索耗时和历史真实模型调用，不把它们合成一个“准确率”。

## 三类教学流程

三类人工编写材料通过正常任务、检索、引用核对、历史与导出流程；使用预设标注，不调用模型。

| 场景 | 候选片段 | 返回证据 | 处理状态 |
|---|---:|---:|---|
| 明确比较 | 1 | 1 | 完成，等待人工核对 |
| 不同条件 | 2 | 2 | 完成，不同测量与研究对象分别保留 |
| 证据不足 | 1 | 0 | 未抽取到表达证据，不作生物学否定 |

这验证页面和数据流程，不能证明模型会正确提取这些内容。材料见[场景数据](../examples/showcase_scenarios.json)，本机记录见[离线验收数据](../examples/portfolio_check_record.json)。

复现三个流程，无需密钥：

```bash
python scripts/portfolio_check.py --output .runtime/my-portfolio-check.json
```

脚本使用临时研究空间，禁止网络及模型客户端，完成后清理自己的临时空间；输出存在时拒绝覆盖。

## 真实本地库检索耗时

已接入索引登记17,300份PDF文件，17,297份可读、3份无可读文本；共106,047条页记录与197,777个片段。
不是去重后的独立研究数量。私有全文和索引不进入公开发布包。

同一节点、单进程、按顺序对每个问题重复五次，使用SQLite FTS5（轻量数据库关键词全文检索），每次最多返回10条论文候选，跳过明显参考文献片段：

| 基因与疾病 | 每次返回候选数 | 五次耗时中位数 |
|---|---:|---:|
| IL6—类风湿关节炎 | 10 | 0.1354秒 |
| ABCC8—2型糖尿病 | 3 | 0.0083秒 |
| CD36—2型糖尿病 | 9 | 0.0180秒 |

这些是该次运行的有限查询测量，受系统缓存、词频和节点负载影响。没有控制冷缓存，没有并发负载测试，不包括模型、联网、全文读取或完整抽取耗时，也没有判断候选的医学相关性。不能据此报告召回率或普遍性能。
索引版本前后一致，没有重建或改写语料。原始逐次时间与索引摘要保存在公开验收记录中；不包含论文内容、文件名或服务器路径。

拥有自己的索引时可复现：

```bash
python scripts/portfolio_check.py \
  --corpus /path/to/corpus.sqlite \
  --output .runtime/my-local-retrieval-check.json
```

## 固定材料的三方法对比工具

新增的`scripts/compare_retrieval_methods.py`（检索组成环节对比工具）用于比较关键词评分、关键词与向量融合、融合加重排序；三种方法调用相同的规范检索函数，使用同一批冻结的候选、查询、别名、文本与最终数量。关键词基线保留现有BM25（关键词评分）及基因、疾病和关系词命中的加分，不冒充另一种纯BM25实现。

它评估的是既有候选内排序，不是“关键词全库独立召回＋向量全库独立召回”。默认最终5、10、15组，分别调用排序函数；先预热，再轮换方法顺序测三次。首次准备、共同粗筛、核心导入与后续排序耗时分别保留，不将缓存命中速度当作全库冷启动速度。

模型运行环境需要已有本地向量模型和重排序模型；网页轻量环境可用于导入人工表。冻结材料是一个结构化文本文件，包含`schema: frozen-retrieval-comparison-v1`、`local_index`（现有BM25格式的固定本地索引）与`queries`（问题列表）。每个问题包含`query_id`（问题编号）、`gene`（基因）、`disease`（疾病）、可选别名和`online_chunks`（事先保存的在线摘要片段）。材料中不填写机器推测的参考答案。工具限定最多20个问题、2000个本地片段、每问题100条在线材料。

```bash
/path/to/model-env/bin/python scripts/compare_retrieval_methods.py run \
  --dataset /path/to/frozen-dataset.json \
  --embedding-model /path/to/local-embedding-model \
  --reranker-model /path/to/local-reranker \
  --output .runtime/my-retrieval-comparison
```

默认两个CPU（中央处理器）线程，固定使用本地模型，禁止网络和付费模型接口。运行目录必须是新目录，避免覆盖人工工作；已有生产缓存不作为该实验的缓存目录。对于耗时作业可在集群允许的作业环境中给命令设置运行时限。

输出包括逐次排名、时间、来源、文字量、输入内容摘要和中文盲核对表。表中不显示方法、排名或机器答案。只填黄色列：判断所给文字是否有疾病相对正常对照的表达量证据，有证据时复制原句并填复核人。前三组的小表可先用于明确核对标准。

```bash
python scripts/compare_retrieval_methods.py score \
  --run-dir .runtime/my-retrieval-comparison \
  --workbook /path/to/completed-review.xlsx \
  --output .runtime/my-retrieval-score.json
```

计分核对原文、目标和来源，拒绝被修改的材料或不在原文中的正例引句。未填、信息不足和失败不当负例。只有某个方法前K个结果均已明确判断时，才计算Precision@K（前K个位置中符合本任务的比例）；不足K条时分母仍为K，并另报实际返回条目中的相关比例。只有该问题整个冻结候选池都完成明确标注，才计算该有限候选池内的召回率；没有已确认正例时召回率未定义，不填写零。按片段计数不等于独立研究数量。

现有旧人工表不自动适用于新的比较任务。尚无当前任务标注时，质量指标明确留空。历史检索缓存有选择偏差，少量开发材料的结果不能当作全库召回率、独立测试成绩或模型抽取方向准确率。

### 首组开发材料的人工核对结果

2026-10-22，完成IL6—类风湿关节炎这一组的前5条结果并集核对，共10个片段。目标是疾病状态相对正常对照的表达量差异。初次填写有6条正例；逐条核查发现3条为治疗效果、2条为参考文献题目、1条为治疗背景。用户明确确认六条范围修正，原始表和确认记录分别保留；不称为独立盲标专家参考。

| 方法 | 本组前5条中符合目标的片段 | 前5条相关比例 |
|---|---:|---:|
| 关键词评分 | 0/5 | 0% |
| 关键词与向量融合 | 0/5 | 0% |
| 融合加重排序 | 0/5 | 0% |

这里的零只指所给前列文字未提供目标表达比较；不表示IL6与类风湿无关，也不是模型抽取准确率为零。本组另27个候选尚未核对，前10/15条相关比例和召回率仍未知。该结果不足以区分三种方法的优劣，也不能代表全部12组或全库表现。

这一案例提示应分别检查：候选中是否存在目标证据、排序有没有把已有证据排后、以及材料是否只讨论治疗或背景。在完成剩余候选判断前，不将原因直接归结为某一个模型，也不按这一组调参后继续把它当作独立测试。
